## Работа

- [ ] Реализовать последовательность: нормализатор → локальные интенты → выбранный fallback-агент.
- [ ] До подключения нормализатора использовать исходный текст через тот же интерфейс.
- [ ] Использовать подтверждённый в 001 API локальной обработки, не определять отсутствие совпадения по тексту ответа.
- [ ] Перенести согласованную в 001 политику локальных фильтров, включая особенности агента с управлением домом.
- [ ] Передавать LLM нормализованный текст и сохранять метаданные запроса и поля результата.
- [ ] Сохранить историю и маршрутизацию продолжения диалога согласно результатам 001.
- [ ] Обработать недоступность fallback, исключения, отмену запроса и очистку состояния разговоров.
- [ ] Подключить streaming только если он подтверждён в 001; корректно объявить возможности entity.
- [ ] Не повторять обработку через LLM при готовом локальном ответе с ошибкой выполнения.

## Критерии готовности

- Локальный результат возвращается без вызова LLM; отсутствие результата вызывает fallback ровно один раз.
- Ошибка выполнения распознанной команды не вызывает повторное действие через LLM.
- Ошибка самого локального обработчика обрабатывается согласно явно описанной политике, без неявного повторного выполнения.
- Два одновременных разговора не смешивают историю и состояние маршрутизации.
- Проверены follow-up LLM, неизменность контекста пользователя и корректное завершение отменённого запроса.
- Тесты проверяют наблюдаемое поведение и отсутствие повторных действий, а не только порядок внутренних вызовов.
