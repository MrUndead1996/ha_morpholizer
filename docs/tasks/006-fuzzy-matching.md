## Критерии готовности

- Есть отложенная выборка, на которой не подбирались пороги.
- Измерены доля правильных замен, ложные замены и отказы; результаты опубликованы вместе с размером корпуса.
- `лампа 1` не превращается в `лампа 2`, а `лампа` не выбирает произвольную `лампа спальни`.
- На неоднозначных запросах исходный текст сохраняется.
- Производительность измерена на каталогах разного размера; целевой бюджет задержки определён по результатам измерений.

## Реализация и ограничения

- Fuzzy по умолчанию выключен. Options: порог 90 (допустимо 85–100), отрыв 8 (5–30); некорректные сохранённые настройки отключают fuzzy. Загрузка словарей и нормализация выполняются в executor.
- `RapidFuzz==3.14.6`, MIT: native extension проверен на x86_64, Python 3.14.4 + HA 2026.11.1. PyPI предоставляет cp314 wheels для x86_64/aarch64 manylinux/musllinux; архитектура устройства пользователя неизвестна, aarch64 аппаратно не проверена. Поэтому пункт проверки целевой архитектуры остаётся открытым.
- Levenshtein normalized similarity без неявного processor; `casefold`, `ё → е`, свёртка пробельных разделителей. Число токенов и пунктуационные разделители должны совпадать. Латиница, цифры, модели и короткие изменяемые слова (<6 символов) не исправляются. Известные разные леммы, глагольные/служебные чтения блокируют замену.
- Точные и морфологические предложения, включая неоднозначные отказы, защищены. Aliases объединяются по entity_id; второй независимый кандидат учитывается даже ниже порога. Общий alias разных целей и конфликтующие максимальные пересечения не разрешаются произвольно.
- Лимиты fuzzy: 4096 символов запроса, 128 токенов, 4096 имён/aliases, 8 токенов/128 символов имени, 250000 потенциальных сравнений. Превышение возвращает `resource_limit`, без частичного fuzzy-поиска. Это **не лимиты предыдущих этапов**; большие каталоги остаются доступны точному/морфологическому поиску.

## Оценка синтетического корпуса

Реальные STT-примеры отсутствуют. Пороги 90/8 — консервативные начальные значения, не подтверждённые полевыми данными. Перед первым запуском holdout исправлены ошибки разметки (точные имена вместо опечаток), затем зафиксирован SHA-256 в `tests/fixtures/fuzzy_holdout.sha256`. После оценки пороги/алгоритм по результатам holdout не менялись. Это небольшая вручную составленная выборка, не независимая оценка реального STT.

`uv run --group integration python -m scripts.evaluate_fuzzy`:

| Выборка | Всего / положительных | Правильные замены | Ложные замены | Отказы на положительных | Правильные отказы | Precision / recall |
|---|---:|---:|---:|---:|---:|---:|
| Development | 32 / 20 | 10 | 0 | 10 | 12 | 1.00 / 0.50 |
| Holdout | 22 / 10 | 10 | 0 | 0 | 12 | 1.00 / 1.00 |

Метрики относятся ко всему pipeline: development содержит 9 fuzzy-замен и 1 морфологическую, holdout — 10 fuzzy-замен. Отказ не считается заменой и не увеличивает precision. Сложные положительные примеры могут оставаться без исправления.

## Производительность

`uv run --group integration python -m scripts.benchmark_fuzzy --sizes 100 1000 5000 --iterations 30`, x86_64 / Python 3.14.4. Имена-соседи синтетические (`Светильник N`), не репрезентативны для любого каталога.

| Имен | Опечатка median / p95, мс | Без совпадения median, мс | Неоднозначность median, мс | Поведение fuzzy |
|---:|---:|---:|---:|---|
| 100 | 2.08 / 2.27 | 0.89 | 2.16 | исправление / безопасный отказ |
| 1000 | 21.10 / 22.50 | 9.18 | 20.84 | исправление / безопасный отказ |

Локальный ориентир для прогретого запроса из трёх токенов и 1000 имён: p95 <50 мс вне event loop; это не обещание для ARM, длинных запросов или холодного запуска. Скорость при 5000 не трактуется как успешный fuzzy-поиск.

## Исправление по ручной проверке

Пользователь сообщил: при включённом fuzzy «что со стиралной машинкой?» не исправляется. Воспроизведено: прежняя метрика считала окончания относительно именительного имени дополнительными ошибками. Теперь для оценки используются известные именные формы **целевого словарного слова**, а подтверждённое склонение соседнего слова не штрафуется. Неизвестный запрос не становится источником предсказанных парадигм; итоговая замена по-прежнему только реальный alias. Кэш форм ограничен 4096 словами, набор — 64 формами; сравнения форм учитываются в общем бюджете. Порог 90/8 и защиты лемм, моделей, коротких слов, неоднозначности сохранены.

Добавлены регрессии для «что со стиралной машинкой?» → «что со Стиральная машинка?» и «Включи стиралную машинку» → «Включи Стиральная машинка»; без fuzzy оба запроса остаются исходными. 204 теста проходят. Повторная оценка development: 12/20 правильных замен, 8 отказов, 0 ложных замен (11 fuzzy, 1 morphology); holdout без изменений. Предыдущие таблицы фиксируют исходную реализацию `33dc892`; после пользовательского примера holdout служит регрессионной, а не новой независимой оценкой. Повторный benchmark: 1000 имён, опечатка median 20.53 / p95 21.50 мс; 5000 по-прежнему `resource_limit`.
