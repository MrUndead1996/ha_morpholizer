## Корпус примеров

- `Что со стиральной машинкой?` → `Что со стиральная машинка?`, если такое имя есть в каталоге.
- Косвенные падежи, множественное число, несколько упоминаний и перекрывающиеся названия.
- Бренды, латиница, номера устройств, регистр и `ё/е`.
- Глаголы, отрицания, числа параметров и пунктуация вне заменяемого названия сохраняются.
- `машинка` и `машина` не считаются одной леммой автоматически; такое соответствие требует alias или последующего fuzzy matching.

## Критерии готовности

- Позитивные и отрицательные примеры оформлены как воспроизводимый корпус.
- Уверенное морфологическое совпадение подставляет существующее имя; неоднозначное сохраняет исходный текст.
- Уже нормализованный текст не изменяется повторно.
- Измерены холодная загрузка, память и задержка обработки; тяжёлые операции не блокируют event loop.

## Реализация и результаты

Зафиксированы `pymorphy3==2.0.6` и `pymorphy3-dicts-ru==2.4.417150.4580142` в manifest и integration-группе окружения. Проверены Python 3.14.4 и HA 2026.11.1. Словари загружаются один раз на entity в executor; кэш разбора ограничен 4096 словами на экземпляр. Только последнее подготовленное поколение имён удерживается в памяти.

Нормализуются только известные словарные русские формы с совместимыми частями речи; латиница и номера внутри имени совпадают буквально, структура пунктуации сохраняется. Реальные aliases подставляются вместо найденных spans. Неоднозначные кандидаты, конкурирующие выходные aliases, пересечения и правдоподобный глагольный разбор не приводят к произвольной замене. Fuzzy matching не добавлен.

Перед применением результата повторно проверяется поколение каталога; если exposure/имена изменились во время анализа, выполняется одна повторная попытка, затем сохраняется исходный текст. LLM follow-up не нормализуется. Внутренняя история содержит одно нормализованное user-сообщение; исходный запрос и trace не мутируются. Attachments и исходное время создания сообщения сохраняются. Live-подписчик может продолжать показывать исходный текст, так как отдельного события редактирования нет.

Полный набор: **105 passed** (`uv run --group integration pytest -q`), Ruff и форматирование пройдены. Из них **50 pure-тестов** дополнительно пройдены в отдельном окружении без установленного HA; лёгкое окружение без runtime-зависимостей — **4 passed, 6 skipped**.

Проверены реальная цепочка «каталог → морфология → русский DefaultAgent → OnOffIntentHandler → однократный тестовый сервис», отсутствие дублирующихся user/assistant в трёх репликах через настоящий dispatcher, bypass и завершение follow-up, неизменность Context и metadata, снятие exposure во время executor job, отмена и безопасная ошибка анализа без локального действия/fallback. Полноценный HA bootstrap, физическое устройство и пользовательский llamacpp в этих новых тестах не участвуют.

Замеры воспроизводятся командой:

```sh
uv run --group integration python -m scripts.benchmark_normalizer --entities 1000 --iterations 100
```

Linux/Python 3.14.4 текущего окружения: холодная загрузка около **48 мс**, RSS около **+23 MiB**, первая обработка около **18 мс**, прогретая медиана **12 мс**, p95 **13 мс** для 1000 синтетических имён. Это не гарантия задержки на устройстве пользователя.
