# Архитектура и границы интеграции

## Решение

Реализовать `ConversationEntity` домена `morpholizer`, которую пользователь выбирает агентом Assist. Существующий llamacpp conversation entity выбирается в настройках Morpholizer; данные и credentials LLM остаются в исходной интеграции.

Реализован маршрутизатор локальных интентов с fallback. Морфология, каталог сущностей и fuzzy matching пока отсутствуют: интерфейс нормализации возвращает исходный текст. Интеграция объявляет `CONTROL`, но не streaming.

Внешняя опция предпочтения локальной обработки выключена: последовательность «нормализация → локальный этап → LLM» выполняет Morpholizer. Для локального этапа используется `conversation.async_handle_intents(hass, user_input, chat_log, intent_filter=None)`, а не обычный ответ агента HA с разбором текста ошибки.

## Политика маршрутизации (задача 003)

- Только `None` из локального API разрешает однократный fallback. В HA это отсутствие строгого совпадения или ошибка сопоставления. Любой `IntentResponse`, включая ошибку выполнения, окончателен: повтор через LLM запрещён.
- Исключение локального обработчика возвращает безопасную ошибку без fallback: действие могло уже частично выполниться. Исключение fallback также не приводит к повтору. Текст исключений и пользовательского запроса не включается в обычные логи.
- Локальный ответ записывается в общий chat log. При делегировании используются ID активного chat log и неизменённые context, language, device/satellite ID, extra system prompt. Результат fallback возвращается без подмены полей.
- Проверка доступности fallback выполняется только после локального промаха: самостоятельные локальные команды работают при недоступном LLM.
- `ConversationResult.continue_conversation=True` закрепляет следующую реплику за тем же fallback. Это поле результата, а не наличие `?` в тексте. Состояние изолировано по сессиям, потребляется перед обработкой следующей реплики и удаляется при cleanup сессии или выгрузке entity. Отмена запроса распространяется вызывающему коду и не инициирует повтор.

### Отличие от штатного фильтра CONTROL

В HA 2026.11.1 `assist_pipeline/default_pipeline.py` передаёт фильтр для агентов с `CONTROL`. Predicate возвращает `True` для `HassGetState` и `HassMediaSearchAndPlay`, а `DefaultAgent.async_handle_intents` **исключает** такие совпадения из локальной обработки. Morpholizer намеренно использует `intent_filter=None`: все штатные интенты должны сначала обрабатываться локально, включая запросы состояния и медиапоиск. Проверки exposed entities и контекст текущего пользователя остаются штатными. Это осознанное отличие, а не точное копирование чекбокса Assist.

## Проверенные исходники целевой версии

При создании каркаса проверены исходники **тега 2026.11.1**, а не только ветка разработки:

- [Python и зависимости HA](https://github.com/home-assistant/core/blob/2026.11.1/pyproject.toml): `requires-python >=3.14.2`.
- [ConversationEntity](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/conversation/entity.py): `_async_handle_message(user_input, chat_log)` и supported languages.
- [Делегирование](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/conversation/agent_manager.py): `async_get_agent` и `async_converse`, включая text/context/language/conversation ID/device ID/satellite ID/extra system prompt.
- [Локальный API](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/conversation/__init__.py) и [DefaultAgent](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/conversation/default_agent.py): строгая обработка exposed entities, семантика `None` и исключающего фильтра.
- [Штатный pipeline](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/assist_pipeline/default_pipeline.py): локальные ответы, фильтр CONTROL и продолжение диалога.
- [ChatSession](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/helpers/chat_session.py): проверка владельца контекста, cleanup неактивных сессий (таймаут 5 минут).

`tests/test_local_intents.py` проверяет реальный русский recognizer, `DefaultAgent`, локальный API и `OnOffIntentHandler` через Morpholizer. Команда «включи кухонный свет» вызывает тестовый сервис ровно один раз и меняет state; ошибка сервиса не вызывает fallback; нераспознанная фраза вызывает его один раз. Использованы настоящий `ExposedEntities` и облегчённые registry-объекты. Полный HA bootstrap и физическое устройство не участвуют.

`tests/test_routing.py` проверяет изоляцию одновременных сессий, явный follow-up и его завершение, cleanup, отмену, передачу текста и контекста, терминальные ошибки и историю return-only агентов. При ошибке обработчика незавершённые tool calls закрываются через `ChatLog.async_add_error` с безопасным сообщением, без исходного текста исключения.

Чтение исходников не является runtime-проверкой. Дополнительно выполнен smoke-эксперимент в установленном HA 2026.11.1 с тестовым `ConversationEntity`: настоящий `async_converse` → Morpholizer → тестовый агент, новый conversation ID и две последовательные реплики. В этом сценарии ID сохраняется и история не содержит дубликатов user/assistant. Автоматическая запись состояний entity и доступ к registry подменены; полноценный запуск интеграции в пользовательском HA не выполнен. Эксперимент закреплён в `tests/test_ha_runtime.py` вместе с проверками делегирования и жизненного цикла.

Точный репозиторий и версия установленной llamacpp-интеграции ещё не зафиксированы. Полноценная проверка реального LLM, его tool history и streaming остаётся частью задачи 001. Streaming в задаче 003 намеренно не включён.

## Контракты

- Одна config entry Morpholizer; fallback выбирается среди существующих conversation entities, исключая собственные сущности Morpholizer.
- Настройки можно изменить через options flow.
- При невозможности делегирования не переключаться неявно на штатный агент HA и не повторять команду.
- Сохранять идентичность пользователя и метаданные запроса при делегировании; это не должно расширять права или exposure.
- Не добавлять второй assistant response поверх результата агента без проверки того, что он уже записал в chat log.
- Никаких credentials LLM в конфигурации Morpholizer.
- Не писать полный текст запросов в обычный лог.

## Ограничения

- Sentence triggers могут обработать исходный текст до выбранного агента независимо от выключенного предпочтения локальных команд. Полный перехват pipeline не входит в выбранную архитектуру.
- Выбор fallback в каркасе ограничен conversation entity ID. Старые агенты, зарегистрированные только по config entry ID без entity, пока не поддерживаются.
- Каркас объявляет только русский язык согласно границам MVP, даже если fallback поддерживает другие языки.
- Прямая обработка через `conversation.process` пройдёт через Morpholizer только при явном выборе его агента.
- Follow-up зависит от корректного `continue_conversation` выбранного агента; по пунктуации ответа он не определяется.
- До подключения настоящей нормализации (005) нужно определить представление исходного/изменённого текста в истории: HA при вложенном вызове с отличающимся текстом может добавить ещё одно user-сообщение. Текущая identity-нормализация этого не вызывает; проверка подменённого нормализатора подтверждает передачу текста и метаданных, но не историю с реальной заменой.
- Защита от прямого self-fallback не заменяет защиту от циклов, создаваемых сторонними агентами-маршрутизаторами. Такие цепочки не являются поддерживаемой конфигурацией MVP.

## Дальнейшее разделение модулей

`conversation.py` остаётся адаптером HA и маршрутизатором; `_normalize_text` — identity-интерфейс до задачи 005. Каталог появится в `catalog.py`; независимая от HA нормализация — в `normalizer.py`, `morphology.py` и `matching.py`. Пустые заглушки этих модулей заранее не создаются.
