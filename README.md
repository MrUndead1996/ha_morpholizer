# Morpholizer для Home Assistant

Экспериментальная custom integration для нормализации названий сущностей в Assist с локальной обработкой команд и fallback на существующий LLM-агент.

Целевое окружение: **Home Assistant Core 2026.11.1**, Python **3.14.2+**, пользовательский **llamacpp conversation agent**.

## Текущий статус

Реализована **локальная маршрутизация**: Morpholizer сначала пробует штатные интенты HA и обращается к выбранному fallback-агенту только при отсутствии локального результата. Ошибка выполнения распознанной команды не запускает повтор через LLM. Объявлена поддержка русского языка.

Нормализатор пока возвращает исходный текст: морфология, fuzzy matching и каталог сущностей ещё не реализованы. Совместимость с конкретной установленной версией llamacpp-интеграции требует проверки.

Целевая цепочка:

```text
STT / текст → Morpholizer → нормализация → локальные команды HA
                                             ├→ результат → ответ
                                             └→ нет результата → LLM → ответ
```

План и критерии готовности: [docs/tasks/README.md](docs/tasks/README.md). Технические границы: [docs/architecture.md](docs/architecture.md).

## Экспериментальная установка

### Через Marketplace / HACS

Начиная с **HA 2026.11**, HACS встроен в Home Assistant как **Marketplace**: отдельно устанавливать HACS не нужно. Morpholizer пока не включён в общий каталог — добавьте его как пользовательский репозиторий.

1. Открыть **Настройки → Marketplace** под учётной записью администратора и принять предупреждение, если оно появится.
2. Нажать **Добавить по ссылке (Add from link)**.
3. Указать репозиторий:

   ```text
   https://github.com/MrUndead1996/ha_morpholizer
   ```

4. При запросе подключить GitHub, следуя инструкциям Marketplace.
5. Нажать **Добавить**. Если тип не определился автоматически, выбрать **Интеграция (Integration)**.
6. Открыть страницу **Morpholizer**, нажать **Установить (Install)** и подтвердить установку.
7. Если Marketplace запросит перезапуск HA, выполнить его. Затем перейти к [настройке интеграции](#настройка-интеграции).

В старом интерфейсе HACS репозиторий добавляется через **⋮ → Пользовательские репозитории (Custom repositories)**: тот же URL, тип **Интеграция**, затем загрузка Morpholizer и перезапуск HA. Это справка по прежнему интерфейсу, а не заявление о поддержке старых версий HA: минимальная целевая версия проекта — **2026.11.1**.

Для установки по ссылке репозиторий должен быть публичным, а файлы интеграции и `hacs.json` — опубликованы на GitHub. Локальные незапушенные изменения Marketplace не увидит. Этот способ установки пока не проверен сквозным тестом.

Официальные инструкции: [Marketplace — пользовательские репозитории](https://next.home-assistant.io/integrations/marketplace/#custom-repositories), [переход с HACS](https://www.hacs.xyz/docs/marketplace/).

### Вручную

1. Скопировать каталог `custom_components/morpholizer` в `<config>/custom_components/morpholizer` Home Assistant.
2. Перезапустить HA.

### Настройка интеграции

1. В **Настройки → Устройства и службы → Добавить интеграцию** найти **Morpholizer**. Если Marketplace уже открыл мастер настройки, продолжить в нём.
2. Выбрать существующий conversation entity, например llamacpp, как fallback-агент. Его собственная интеграция должна быть уже настроена и загружена.
3. Для проверки в отдельном тестовом Assist выбрать Morpholizer как conversation agent.

4. **Выключить «Предпочитать локальную обработку команд»** в настройках Assist: локальный этап теперь выполняет сам Morpholizer. Иначе штатный этап может обработать запрос до него.

Morpholizer пробует все штатные локальные интенты, в том числе запросы состояния и медиапоиск, независимо от возможностей fallback. Это намеренное отличие от фильтра штатного Assist для LLM с управлением домом. Штатные ограничения exposure и контекст пользователя сохраняются.

Если LLM вернул `continue_conversation=True` (например, задал уточняющий вопрос), следующая реплика в той же сессии идёт непосредственно ему. После завершения уточнения возвращается порядок «локально → fallback». При недоступном LLM самостоятельные локальные команды продолжают работать.

Ассистент может обработать sentence triggers до вызова выбранного агента. Каркас не изменяет HA monkey patch-ами и не перехватывает эти ранние triggers. Для прямого `conversation.process` нужно явно указать entity ID Morpholizer.

## Разработка

Нужны Python 3.14.2+ и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```sh
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Лёгкие проверки проверяют структуру, метаданные, переводы и синтаксис. Дополнительные smoke-тесты используют настоящие классы HA 2026.11.1 и подменяют внешнего агента и отдельные интерфейсы при проверке каркаса:

```sh
uv sync --locked --group integration
uv run --group integration pytest
```

В обычном окружении без HA интеграционные модули пропускаются. Тесты проверяют маршрутизацию, ошибки, историю, follow-up и отмену запросов, но **не заменяют запуск интеграции в пользовательском HA**. Проверка реального llamacpp остаётся в задаче [001](docs/tasks/001-routing-spike.md).

Структура:

```text
custom_components/morpholizer/  # устанавливаемый runtime интеграции
tests/                         # проверки каркаса
docs/tasks/                    # план реализации
.github/workflows/             # автоматические проверки
pyproject.toml                 # инструменты разработки
uv.lock                        # фиксированное окружение проверок
hacs.json                      # начальная конфигурация HACS
```

Добавление по ссылке не означает включения в общий каталог Marketplace / HACS. Перед подачей в каталог требуется завершить проверки, выбрать лицензию и добавить brand assets. Лицензия не назначена автоматически.
