# Morpholizer для Home Assistant

Morpholizer помогает Assist узнавать **русские названия устройств, областей и этажей в разных падежах и с опечатками**. Он подставляет настоящее имя или псевдоним цели, пробует выполнить запрос штатными средствами Home Assistant и обращается к выбранному LLM-агенту только при отсутствии локального результата.

```text
Голос → STT ─┐
            ├→ Morpholizer → нормализация → локальные интенты HA
Текст ──────┘                                  ├→ результат → ответ
                                               └→ нет результата → LLM → ответ
```

> [!IMPORTANT]
> Экспериментальная интеграция. Целевая версия — **Home Assistant Core 2026.11.1**. Нечёткий поиск (fuzzy) по умолчанию выключен. Перед использованием с важными устройствами проверьте работу на безопасной тестовой сущности.

## Возможности

- **Склонения:** «со стиральной машинкой» сопоставляется с именем «Стиральная машинка».
- **Опечатки:** при включённом fuzzy «со стиралной машинкой» также может найти это имя.
- **Имена и псевдонимы (aliases):** используются только сущности, доступные Assist. Переименование, смена aliases и доступности учитываются без перезапуска.
- **Области и этажи:** «в спальне» сопоставляется с областью «Спальня», «на втором этаже» — с этажом «Второй этаж». Поддерживаются их aliases, переименование и удаление без перезапуска. Области/комнаты (areas) не следует путать с географическими сущностями `zone.*`.
- **Локальные команды перед LLM:** распознанная команда или запрос состояния обрабатывается средствами HA. Ошибка выполнения не запускает повтор через LLM.
- **Продолжение диалога:** если LLM явно ожидает ответ на уточнение, следующая реплика в той же сессии идёт непосредственно ему, без нормализации и локального этапа.

Нормализация работает локально. Morpholizer не заменяет STT, не содержит собственной LLM и не требует её ключей: подключение к модели настраивается в интеграции выбранного резервного агента.

## Установка

### Через Marketplace / HACS

Morpholizer не включён в общий каталог; добавьте его как пользовательский репозиторий.

1. В HA 2026.11 откройте **Настройки → Marketplace → Добавить по ссылке (Add from link)**.
2. Укажите адрес:

   ```text
   https://github.com/MrUndead1996/ha_morpholizer
   ```

3. При необходимости подключите GitHub и выберите тип **Интеграция (Integration)**.
4. Откройте **Morpholizer → Установить (Install)** и следуйте мастеру настройки.

В прежнем интерфейсе HACS: **⋮ → Пользовательские репозитории (Custom repositories)** → тот же адрес → тип **Интеграция** → загрузка и перезапуск HA. Это альтернативный путь интерфейса, а не обещание совместимости со старыми версиями HA.

При обновлении интеграции перезапускайте HA. Установка через Marketplace пока не проверена сквозным тестом проекта; [официальная справка](https://next.home-assistant.io/integrations/marketplace/#custom-repositories).

### Вручную

1. Скачайте репозиторий и скопируйте папку `custom_components/morpholizer` в `<config>/custom_components/morpholizer` вашего HA.
2. Перезапустите Home Assistant. Зависимости установятся автоматически.
3. Перейдите к настройке ниже.

Для обновления замените ту же папку и перезапустите HA.

## Настройка

1. Установите и настройте резервного conversation-агента, например llamacpp. Он должен быть загружен и доступен в HA.
2. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Morpholizer**. Если Marketplace уже открыл мастер, продолжите в нём.
3. Выберите **Резервный conversation-агент** — существующую сущность `conversation.*` вашего LLM.
4. В настройках голосового ассистента Assist выберите **Morpholizer** как разговорного агента и русский язык.
5. **Выключите «Предпочитать локальную обработку команд».** Локальный этап выполняет сам Morpholizer; иначе HA может обработать запрос до нормализации.
6. Убедитесь, что нужные сущности доступны Assist, и проверьте их имена и aliases.

Для команд по расположению назначьте устройства областям, а области — этажам в HA. Отдельно включать нормализацию областей/этажей не нужно: морфология работает всегда, исправление опечаток — при общей опции fuzzy. Используются все зарегистрированные области и этажи, включая пустые, как у штатного агента HA; это не делает скрытые устройства доступными Assist.

Запись интеграции может быть только одна. Morpholizer нельзя выбрать собственным резервным агентом. YAML-настройка интеграции не предусмотрена.

## Параметры

Откройте **Настройки → Устройства и службы → Morpholizer → параметры интеграции**. Изменения сохраняются и вызывают её перезагрузку.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| Резервный conversation-агент | Выбирается при настройке | Получает запрос, если локального результата нет |
| Включить нечёткий поиск названий объектов | Выключено | Исправлять осторожно отобранные опечатки после точного и морфологического поиска |
| Минимальная оценка нечёткого совпадения | **90**, диапазон 85–100 | Насколько похож фрагмент на имя; больше — строже |
| Минимальный отрыв от следующего совпадения | **8**, диапазон 5–30 | Разница оценок между лучшими кандидатами разных сущностей; больше — осторожнее |

Для начала оставьте **90 / 8**. Оценка сходства — не вероятность правильного действия. Aliases одной цели (сущности, области или этажа) не конкурируют друг с другом. При неоднозначности fuzzy отказывается от замены, а не выбирает первую цель. Некорректные сохранённые параметры отключают fuzzy.

## Примеры и проверка

Допустим, доступная Assist сущность имеет имя или alias **«Стиральная машинка»**:

| Запрос | Текст после нормализации | Условие |
| --- | --- | --- |
| `Что со стиральной машинкой?` | `Что со Стиральная машинка?` | Морфология, fuzzy не требуется |
| `Включи стиральную машинку` | `Включи Стиральная машинка` | Морфология, fuzzy не требуется |
| `что со стиралной машинкой?` | `что со Стиральная машинка?` | Fuzzy включён, параметры 90 / 8 |
| `Включи стиралная машинка` | `Включи Стиральная машинка` | Fuzzy включён, параметры 90 / 8 |

Это примеры замены названия, а не новые шаблоны команд: итоговый ответ зависит от локальных интентов HA и резервного агента. Необычное окончание в итоговом тексте намеренно — подставляется реальное имя, а не грамматически отредактированная фраза.

Для областей и этажей действуют те же правила:

| Запрос | Имя/alias в HA | Текст после нормализации |
| --- | --- | --- |
| `Включи свет в спальне` | Область `Спальня` | `Включи свет в Спальня` |
| `Включи свет в гостевой комнате` | Alias области `Гостевая комната` | `Включи свет в Гостевая комната` |
| `Включи свет на втором этаже` | Этаж `Второй этаж` | `Включи свет на Второй этаж` |
| `Включи свет на верхнем этаже` | Alias этажа `Верхний этаж` | `Включи свет на Верхний этаж` |

Опечатки в длинных названиях тоже поддерживаются при включённом fuzzy, например `на мансарднном этаже` → `на Мансардный этаж`. Название должно существовать в реестре или aliases. Цифра `2` не преобразуется в слово «второй» автоматически — для альтернативного названия добавьте alias.

### Быстрая проверка в HA

Начните с текстового Assist и безопасной тестовой сущности, затем повторите голосом:

1. Проверьте склонённое имя при выключенном fuzzy.
2. Включите fuzzy с 90 / 8 и проверьте опечатку, в том числе со склонением.
3. Отключите fuzzy и повторите: нечёткая замена больше не должна применяться.
4. Измените alias без перезапуска HA и проверьте новое имя. После отключения доступности Assist сущность не должна участвовать в нормализации.
5. Задайте свободный вопрос и ответьте на уточнение LLM в той же сессии.
6. Перезапустите HA: параметры должны сохраниться.

Для областей и этажей дополнительно проверьте команды из таблицы выше и убедитесь, что меняются только доступные Assist устройства в указанном расположении. Проверьте переименование области/этажа и смену aliases без перезапуска. Новая функциональность пока проверена автоматически, но не в пользовательском HA.

Для защитных сценариев проверьте разные номера (`Термостат 2` и запрос `термостта 3`) и одинаковое имя у двух сущностей. Morpholizer не должен менять номер или произвольно разрешать коллизию.

> [!WARNING]
> Отказ от нормализации **не запрещает последующую обработку LLM**. Резервный агент может самостоятельно понять опечатку и выполнить действие. Проверяйте маршрут в трассировке Assist: успешное действие само по себе не доказывает, что сработал fuzzy.

## Ограничения

- Поддерживается русский язык. Области и этажи нормализуются по именам/aliases; выбор конкретных устройств и контекст комнаты остаются в ведении HA. Географические `zone.*` не обрабатываются как области.
- Одинаковые или близкие имена разных целей могут приводить к отказу от замены, в том числе при коллизии между сущностью, областью и этажом. Тип цели не угадывается по предлогу; для надёжного выбора используйте уникальные aliases.
- Morpholizer меняет только найденные названия. Глаголы, отрицания и параметры вне них не переписываются. Это не отдельная система безопасности для команд LLM.
- «Машина» и «машинка» — разные словарные леммы. Для такого соответствия добавьте alias, а не снижайте fuzzy-порог.
- Fuzzy не угадывает изменённые слова короче 6 символов, латинские названия и числовые модели. Количество слов и внутренняя пунктуация должны совпадать. Регистр, пробелы и `ё/е` учитываются при сравнении.
- При слишком большом запросе или каталоге fuzzy пропускается; точный и морфологический этапы остаются. Точные лимиты приведены в технических деталях ниже.
- Ошибка выполнения локальной команды или исключение локального обработчика окончательны: повтора через LLM нет, поскольку действие могло частично выполниться. При недоступном LLM самостоятельные локальные команды продолжают работать.
- Продолжение диалога зависит от флага `continue_conversation`, возвращаемого агентом, а не от вопросительного знака в ответе.
- Streaming ответов не поддерживается. Fallback должен иметь сущность `conversation.*`; старые агенты только с config entry ID и цепочки сторонних маршрутизаторов не являются поддерживаемой конфигурацией.
- Ранние sentence triggers Assist могут обработать исходную фразу ещё до вызова Morpholizer, даже при выключенном предпочтении локальных команд. Глобального перехвата pipeline нет.
- Исходный текст в трассировке или live-интерфейсе может отличаться от нормализованного текста во внутренней истории. Это само по себе не означает, что замена не произошла.

## Решение проблем

| Проблема | Что проверить |
| --- | --- |
| Интеграции нет в списке | При ручной установке проверьте путь `<config>/custom_components/morpholizer`, перезапустите HA, обновите страницу или очистите кэш браузера. Посмотрите журнал ошибок загрузки |
| Резервный агент не принимается | Его интеграция должна быть загружена, сущность `conversation.*` — существовать и быть доступной. Нельзя выбрать сам Morpholizer |
| Название не исправляется | Выбран ли Morpholizer в Assist, выключено ли предпочтение локальных команд, доступна ли сущность Assist, совпадает ли ожидаемый alias. Для опечатки дополнительно включите fuzzy |
| Опечатка всё равно не исправляется | Это может быть безопасный отказ: короткое слово, другая лемма, номер/модель, несколько близких целей или лимит поиска. Сначала проверьте точное имя и добавьте понятный уникальный alias |
| Команда выполняется и без fuzzy | Её мог понять локальный HA или LLM. Сравните маршруты в трассировке Assist, а не только ответы |
| После отказа устройства ответ не пришёл от LLM | Ошибка выполнения локальной команды намеренно не запускает fallback — это защита от повторного действия |

Если проблема воспроизводится, [создайте issue](https://github.com/MrUndead1996/ha_morpholizer/issues) и приложите:

- версию HA, версию/коммит Morpholizer и архитектуру устройства;
- название, репозиторий и версию резервной интеграции;
- точный введённый текст или транскрипт STT, ожидаемое имя/alias и результат;
- параметры fuzzy, маршрут из трассировки Assist и относящиеся к ошибке записи журнала.

Перед публикацией удалите персональные данные и секреты. Обычные логи Morpholizer не содержат полного текста запросов; подробные счётчики маршрутов и задержек пока не реализованы.

## Разработка

Нужны Python **3.14.2+** и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```sh
uv sync --locked --group integration
uv run ruff check .
uv run ruff format --check .
uv run --group integration pytest -q
```

Для лёгких проверок без установки HA: `uv sync --locked` и `uv run pytest -q`. Недоступные runtime-зависимости приводят к пропуску соответствующих модулей тестов.

Код интеграции находится в `custom_components/morpholizer/`, тесты — в `tests/`, воспроизводимые оценки — в `scripts/`. Правила изменений описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

### Совместимость и состояние проверок

| Компонент | Проверено |
| --- | --- |
| Home Assistant Core | **2026.11.1**; другие версии не заявлены как проверенные |
| Python / платформа | **3.14.4 / Linux x86_64**; aarch64 аппаратно не проверена |
| LLM | Пользователь подтвердил маршрутизацию с llamacpp; точный репозиторий и версия интеграции не зафиксированы |
| Морфология и каталог | Автоматические проверки и подтверждённая пользователем проверка в HA |
| Fuzzy | Автоматические проверки; исправление сочетания опечатки со склонением ждёт повторной ручной проверки |
| Области и этажи | Автоматические проверки имён/aliases, обновлений и локального выполнения; ручная проверка в HA ещё нужна |

Последний полный прогон: **229 тестов** с HA; **148 тестов, 7 пропущенных модулей** в отдельной среде без HA. Есть проверки реального русского recognizer и однократного вызова тестового сервиса через Morpholizer, истории, follow-up, ошибок, отмены, exposure, смены каталога во время executor job и настроек. Для областей/этажей проверено, что скрытые устройства и устройства в другом расположении не затрагиваются. Они не заменяют сквозную проверку пользовательского STT, физического устройства и конкретной LLM.

До стабильного релиза остаются проверка полного голосового маршрута и обновления/установки, фиксация версии fallback и архитектуры, сбор реальных ошибок STT, расширение диагностики, выбор лицензии и подготовка brand assets для общего каталога. Streaming остаётся неподдерживаемым.

<details>
<summary>Технические детали: маршрутизация и нормализация</summary>

- `conversation.py` — адаптер `ConversationEntity`; `catalog.py` — обновляемый каталог; `normalizer.py`, `morphology.py`, `matching.py` — независимые от HA модули анализа.
- Локальный вызов — `conversation.async_handle_intents(..., intent_filter=None)` в [HA 2026.11.1](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/conversation/__init__.py). Только `None` разрешает однократный fallback. Любой локальный `IntentResponse`, включая ошибку, окончателен. Намеренно пробуются все локальные интенты, включая запрос состояния и медиапоиск, без CONTROL-фильтра штатного Assist.
- При делегировании сохраняются активный conversation ID, context пользователя, язык, device/satellite ID и extra system prompt. Уточнение LLM закрепляет следующую реплику за тем же агентом; состояние изолировано по сессиям и очищается вместе с ними.
- Каталог использует штатные `intent.async_get_entity_aliases` и `async_should_expose` для сущностей. Он не расширяет права или exposure. Без state запись исключается; `unknown`/`unavailable` не удаляют имя. Комната берётся с сущности, затем устройства с учётом родительского устройства. Все имена/aliases из area/floor registry сохраняются отдельными неизменяемыми записями; есть подписки на изменения обоих реестров. Подписки снимаются при выгрузке.
- Снимки каталога неизменяемы. После анализа повторно проверяется поколение: при изменении выполняется одна повторная попытка, затем сохраняется исходный текст. Ошибка перестройки не разрешает использовать устаревший каталог.
- Приоритет: точное имя → известные совместимые словарные леммы → opt-in fuzzy. Нормализатор возвращает текст и структурированные решения с исходными offsets, методом, кандидатами и причиной отказа. Замена — только реальное имя/alias. Предыдущие совпадения и неоднозначные отказы защищены от fuzzy.
- Fuzzy использует Levenshtein normalized similarity без неявного processor. Для сочетания опечатки со склонением сравнивает с формами известного целевого слова; не строит парадигму из предполагаемой опечатки. Проверенные разные леммы и глагольные/служебные чтения блокируют замену. Короткое слово может лишь склоняться по подтверждённой общей лемме и части речи (например, «этаже» → «этаж»), но не исправляться нечётко. Кандидаты ранжируются по независимым целям `(kind, id)`, включая второго кандидата ниже порога; совпадение ID области и этажа не объединяет их aliases.
- Лимиты fuzzy: **4096 символов / 128 токенов запроса**, **4096 имён/aliases суммарно для сущностей, областей и этажей**, **8 токенов / 128 символов имени**, **250000 сравнений**, включая сравнения словоформ. Превышение возвращает `resource_limit`, без частичного fuzzy-результата. Эти лимиты не ограничивают предыдущие этапы.
- Словари загружаются, а нормализация выполняется в executor. Кэши анализа и словоформ ограничены 4096 словами на экземпляр, набор форм — 64; разбор защищён lock. В памяти удерживается только последний подготовленный набор имён.
- В истории обновляется текущее user-сообщение, без дубликата при вложенном dispatch. Attachments и время создания сохраняются, исходный `ConversationInput` не мутируется. Отдельное событие редактирования live-сообщения не отправляется.

</details>

Корпус вручную составлен из синтетических опечаток/STT-подобных примеров, **не из реальных транскриптов пользователя**. Порог 90 / отрыв 8 — начальные консервативные значения, не подтверждённые полевыми данными.

| Выборка | Всего / положительных | Правильные замены | Ложные замены | Отказы на положительных | Правильные отказы | Precision / recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Development | 32 / 20 | 12 | 0 | 8 | 12 | 1.00 / 0.60 |
| Holdout | 22 / 10 | 10 | 0 | 0 | 12 | 1.00 / 1.00 |

Метрики относятся ко всему pipeline: development — 11 fuzzy-замен и 1 морфологическая, holdout — 10 fuzzy-замен. Правильные отказы не увеличивают precision. Положительный пример может безопасно остаться без исправления. Holdout зафиксирован SHA-256 в `tests/fixtures/fuzzy_holdout.sha256` до первого запуска, без настройки порогов по нему; после исправления по пользовательскому примеру служит регрессионной, а не новой независимой оценкой.

На Linux x86_64 / Python 3.14.4, для прогретого запроса из трёх токенов и синтетических соседних имён `Светильник N`:

| Имен | Задержка опечатки median / p95 | Результат |
| ---: | ---: | --- |
| 100 | 2.11 / 2.18 мс | Fuzzy-замена |
| 1000 | 20.53 / 21.50 мс | Fuzzy-замена |
| 5000 | 42.17 / 43.23 мс | Fuzzy пропущен: `resource_limit` |

В замере на 5000 имён учтена работа предыдущих этапов: это **не успешный fuzzy-поиск**. Локальный ориентир — p95 <50 мс на 1000 имён; он не гарантируется на ARM, длинных запросах или холодном запуске. Ранее измеренная холодная загрузка морфологии — около 48 мс и +23 MiB RSS, без обещания таких же значений на устройстве пользователя.

Лицензия самого проекта пока не выбрана; наличие публичного репозитория не заменяет условий распространения. Перед стабильным релизом их должен определить владелец.

Лицензия кода библиотек и упаковки словарей — MIT, словарных данных — CC BY-SA 3.0. Словари не скопированы в репозиторий; зависимости устанавливает HA. RapidFuzz проверен с native extension на x86_64; наличие cp314 wheels для aarch64 manylinux/musllinux не является аппаратной проверкой.
